# new-api 性能测试简报

汇报日期：2026 年 9 月 19 日

**目前情况：已完成高并发和长流式响应两类测试。2,000 并发短时测试表现较好，3,000 并发起出现明显失败；1,000 并发长流式请求成功率为 98.46%，仍需优化。服务器监控未显示整机 CPU、内存耗尽，但压测机存在明显负载压力，目前尚不能确认 new-api 的实际容量上限。**

**一、测试范围**

采用最新两轮报告，时间均为北京时间：

- **stress 高并发测试**：9 月 19 日 14:50–14:58，从 2,000 逐步增加至 4,000 并发，再降回 2,000；每档固定负载统计 50 秒。
- **longstream 长流式测试**：9 月 19 日 15:15–15:19，1,000 并发，计划运行 3 分钟，结束后等待在途请求完成；实际请求全部为流式。

两轮均使用模拟模型上游（Mock），用于观察 new-api 转发链路的表现，不代表真实模型供应商的服务能力。并发数指压测工具模拟的同时请求用户数，不等于日活用户数。

**二、new-api 链路性能**

高并发测试共发起 **91,704 次请求**，成功 **71,220 次**，全程成功率 **77.66%**。分档结果如下：

| 测试阶段 | 请求成功率 | 每秒成功完成请求数 | 成功请求完成耗时 P95 |
|---|---:|---:|---:|
| 2,000 并发 | 100.00% | 300.62 次/秒 | 8.83 秒 |
| 2,500 并发 | 99.81% | 283.62 次/秒 | 16.58 秒 |
| 3,000 并发 | 46.20% | 121.60 次/秒 | 25.13 秒 |
| 3,500 并发 | 41.71% | 99.72 次/秒 | 32.36 秒 |
| 4,000 并发 | 42.23% | 85.40 次/秒 | 33.32 秒 |
| 降回 2,000 并发 | 84.00% | 119.60 次/秒 | 22.43 秒 |

P95 表示约 95% 的成功请求在该时间内完成，包含上游响应时间。成功率按请求发起档位统计；每秒成功数按该时间窗口实际完成事件统计，两者口径不同。

**解读：**2,000 并发档观察到约每秒 301 次成功请求；2,500 并发时响应已明显变慢，P95 超过本轮设置的 15 秒门槛；3,000 并发及以上成功率降至约 42%–46%。降载后的 50 秒观察窗口内，也未恢复到初始水平。

| 长流式测试指标 | 结果 |
|---|---:|
| 并发数 | 1,000 |
| 总请求 / 成功 / 失败 | 3,047 / 3,000 / 47 |
| 全程成功率 | 98.46% |
| 首字等待时间（中位数 / P95） | 1.96 秒 / 5.69 秒 |
| 完整响应耗时（中位数 / P95） | 72.55 秒 / 78.19 秒 |
| 固定负载窗口每秒成功完成请求数 | 11.77 次/秒 |

**解读：**大部分长流式请求能够完整完成，但成功率仍低于本轮 99% 的目标。完整响应约一分钟以上包含持续输出过程，应结合首字等待和流式完整性评价，不能直接套用普通短请求的 15 秒完成门槛。

监控覆盖 3 台 new-api 实例，以及数据库、缓存和模拟上游。下表采用测试全程内完整分钟的数据，含请求排空阶段；stress 为 7 个完整分钟，longstream 为 3 个完整分钟。

| new-api 最高内存使用率（分钟均值） | 2.3% | 2.1% |

已采集区间内，new-api 实例状态检查失败数为 0，NAT 端口分配错误和丢包数均为 0。以上为分钟级监控，不能排除秒级尖峰、单核或连接池等局部瓶颈；网络数值也不能单独证明带宽充足。服务器规格及 new-api 部署版本未在本轮报告中填写，暂不作推定。

**四、当前问题与下一步**

1. **高并发失败及恢复问题需要定位。**stress 共失败 20,484 次，其中工具归类为 client_error 的有 19,976 次，另有 329 次超时、91 次 HTTP 5xx、88 次流不完整。client_error 是工具分类，不能据此直接认定是客户端责任；需关联 new-api、负载均衡及上游日志确认原因。
2. **压测机可能影响结果。**两轮压测机 CPU 峰值均接近 100%；stress 测量进程每秒事件循环 P99 的最大值达 9.89 秒。建议使用独立云端压测机或分布式压测，先排除发压和测量环节的限制。
3. **完成复测后再确定运营容量。**优先复测 2,000–2,500 并发及 1,000 并发长流式场景，延长持续时间，验证失败率和降载恢复，再补充真实上游测试。当前可把 2,000 并发作为复测参考点，不作为已承诺的生产容量。

两份原报告均标记“待核实”，分别缺少 163 条、31 条流式测量记录，部分监控及环境信息也待补全。因此，目前的结论是：**已有短时承载能力数据，服务器整体资源尚有余量迹象，但高负载稳定性和真实可用容量仍处于验证阶段。**
